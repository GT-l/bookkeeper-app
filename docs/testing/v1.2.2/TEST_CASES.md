## 二、判因结论与证据

结论：**系统主动撤销了无障碍授权**，不是 App 崩溃、不是 ANR、不是识屏逻辑报错、也不是「长时间后台运行后被省电杀掉」。

| 证据 | 推理 |
| --- | --- |
| `系统开关：关` 且 `wasEnabled=true` | `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 里本服务已被系统移除；进程被杀时开关通常仍是「开」 |
| onUnbind 与 onDestroy 只隔 1~14ms | 这是「绑定被解除 → Service 无其他绑定 → 正常销毁」的标准生命周期，不是崩溃堆栈 |
| 存活仅 1 秒 / 27 秒 | 秒级撤销属于「开启后立刻被系统复核重置」，不符合后台省电清理的时间尺度 |
| 全程无崩溃 / ANR / 解析失败日志 | 服务的零异常逃出设计生效，问题在系统侧 |

高概率成因（按优先级）：

1. **Android 13+ 侧载 APK 的「受限设置」**：APK 从 GitHub 下载安装，非应用商店来源；系统会对侧载应用的无障碍授权做拦截或复核后重置。
2. **vivo / iQOO（OriginOS）安全与省电策略**：vivo 官方对「无障碍开关自动关闭」给的解法是把应用加入「后台高耗电」与「一键加速白名单」。
3. 系统级授权被外部工具（如无障碍锁定类工具）周期性改写。

> 应用层无法写 `Settings.Secure` 改这个开关（需系统签名 / Shizuku / root）。因此 App 侧只能做「检测 + 可判因日志 + 系统侧引导」，不能内置保活修复。

## 三、本轮代码改动对照

| 编号 | 问题 | 修复 | 静态断言 |
| --- | --- | --- | --- |
| D-01 | 诊断只有状态没有结论，用户只能自己看日志 | `AccessibilityHealth.diagnose()` 输出人话判因，弹窗与复制的 log 都带结论 | T-DIAG-01 / 05 / 06 |
| D-02 | `onUnbind` / `onDestroy` 文案写成「被系统销毁 / 进程退出」，把排查方向带偏 | 改为「系统撤销授权」「解绑后的正常销毁，非崩溃证据」 | T-LOG-03 / 05 |
| D-03 | 只记录断开不记录连接，复制回来的 log 全是 ERROR | 新增 `CaptureLog.forceInfo`，连接事件强制落盘，含次数 / pid / 进程已运行时长 / 截屏能力 | T-LOG-01 / 02 |
| D-04 | 日志缺存活时长，无法区分「秒关」和「后台被杀」 | 记录 `KEY_LAST_LIFESPAN`、pid、累计连接次数、累计被撤销次数、安装来源 | T-LOG-04 / T-DIAG-04 / 05 |
| D-05 | **vivo 机型完全看不到稳定运行设置卡片**（`needsOppoGuidance()` 只判 OPPO 系） | `RomCompat.isVivoFamily()` + `needsKeepAliveGuidance()`，UI 改调用新判断并按厂商显示标题 | T-ROM-01..04 |
| D-06 | 引导漏了 Android 13+ 侧载「允许受限设置」 | 列为稳定运行设置第 1 步，报告里带上安装来源 | T-DIAG-02 / 04 |
| D-07 | 引导用通用「电池不限制」，vivo 官方要的是「后台高耗电 + 一键加速白名单」 | vivo / iQOO 分支给专属两条，路径改为「设置 → 快捷与辅助 → 无障碍 → 已下载的服务」 | T-DIAG-03 |
| D-08 | 关于页停在 v1.2.1 | 新增 v1.2.2 更新介绍 | T-A11Y-04 |
