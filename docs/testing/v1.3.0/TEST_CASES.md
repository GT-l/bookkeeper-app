# v1.3.0 测试用例 · 识屏准确度与自动化

> 测试对象：v1.3.0（versionCode 7）。目标：解决「打开付款界面识别不到」「微信所有付款界面识别失败」「重复确认强制跳软件界面」，并整体提升识屏准确度与自动化。
> 本机无 JDK / Android SDK / 模拟器；编译与单测以 GitHub Actions 为准，真机项需用户执行。

## 一、市面方案调研结论

| 来源 | 可借鉴做法 | 本轮落地 |
| --- | --- | --- |
| 咔皮记账 | 自动记账分「全自动 / 悬浮球 / 通知卡片」三种模式，设置页把权限、稳定运行、识别场景分开引导；支付完成后弹出识别结果，点确认即记账 | 底部悬浮确认卡片 + 校对链优先悬浮 |
| 花有谱 / 慧铭记账 | 实测**部分微信支付成功页在普通无障碍服务下只返回空根节点**；按页面身份做有界重读、窗口归属复核、深层容器遍历；区分实付金额与营销金额；切后台再回来不重复入账 | className 强信号 + 3 次有界重读 + 多窗口读取 + 内容指纹去重 |
| BillRecord | 五层文本提取（DFS 节点 → 关键词 → 事件回溯 → 多窗口 → OCR）、5s 冷却防重复、TYPE_APPLICATION_OVERLAY 悬浮确认卡片 | 5s 内容指纹冷却、多根节点读取、底部悬浮卡片 |
| CSDN 支付结果解析框架 | `BaseBillParser` + 平台专用 `WeChatParser`，按「支付成功」节点位置取相邻金额/商户 | `refineWeChatText()` 把金额/商户补成 `金额：` / `商户：` 标签行 |

## 二、三个问题的根因

| 现象 | 根因（代码位置） | 修复 |
| --- | --- | --- |
| 打开付款界面识别不到 | 旧链路只在 `isPaymentComplete()` 命中 6 个完成态词时才响应；完全不看 `className` / 页面类型 | 新增 `PaymentScreenRecognizer`，识别 ENTRY / SUCCESS / DETAIL / UNKNOWN |
| 微信所有付款界面失败 | ① 1.5s 去抖「解析前先占位」，第一个中间态事件吃掉窗口，结果页事件被丢；② `event.source` 常是局部子树；③ 节点跨线程遍历可能失效；④ 6 个关键词不覆盖「已完成 / 微信支付」；⑤ 微信结果页可能返回空根节点；⑥ 子进程包名 `com.tencent.mm:tools` 被精确匹配丢弃 | 内容指纹 5s 冷却（失败不占窗口）、活动窗口 + 多窗口读取、主线程文本快照、扩展词表、className 有界重读、包名归一化 |
| 重复确认强制跳软件界面 | `ShakeQuickAddService.showDuplicateConfirm / showQuickConfirm` 直接 `startActivity(QuickConfirmActivity)`；`VerificationController` 只在 `verify_mode==1` 才用悬浮窗 | 改为底部悬浮卡片；校对链优先底部卡片；无权限降级为点击才打开的普通通知 |
