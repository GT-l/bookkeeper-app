# v1.3.0 测试报告

> 对象：v1.3.0（versionCode 7），识屏准确度与自动化专项。
> 静态测试在本机执行；编译 / 单测以 GitHub Actions 为准；真机流程需用户确认。

## 一、结论摘要

本轮把识屏从「整页文本里找 6 个完成态词」升级为「页面识别 + 多信号融合 + 分层确认」：

- **认得出付款界面**：新增纯 Kotlin 页面识别器，用 Activity 类名 + 分平台文案区分付款界面 / 收银台 / 支付成功页 / 账单详情。
- **修好微信全场景失败**：定位到「1.5s 去抖解析前占位吞事件」这一主因，配合局部子树、跨线程节点、词表过窄、微信空根节点、子进程包名五个次级原因，逐一修复。
- **确认不再打断**：重复确认与中低置信度改为屏幕底部悬浮卡片，无权限时降级为点击才打开的普通通知。

调研参照：咔皮记账（识别场景分层 / 通知卡片）、花有谱与慧铭记账（微信支付成功页空根节点、有界重读、页面身份）、BillRecord（多层文本提取、5s 冷却、悬浮确认卡片）。

## 四、设计约束与边界

- **不绕过 QA F-02**：置信度加成只影响阈值判断，`categoryId<=0 || accountId<=0` 仍强制转校对，绝不产生「无分类账单」。
- **不虚假声明 `isAccessibilityTool`**：Android 17 高级保护模式对非辅助类应用有硬限制，但记账 App 不是残障辅助工具，本轮未用该标记冒充。
- **悬浮窗是权限依赖能力**：未授予 `SYSTEM_ALERT_WINDOW` 时降级为普通通知（点击才打开），不自动拉起 Activity，符合 Android 10+ 后台启动限制。
- **页面识别是启发式**：依赖 Activity 类名与可见文案，微信 / 支付宝改版可能改变类名或页面结构；真机 TC-02/03 仍需确认，日志保留 `cls=` / `len=` 便于后续补规则。
- 本机没有 Android 设备，无法验证真实节点树；CI 绿色只证明编译与单测通过，不证明微信各付款场景已被覆盖。
