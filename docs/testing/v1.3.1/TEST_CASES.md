> 覆盖高置信度静默入账、底部轻卡片、重复检测、抖音订单页、摇一摇与自动识屏一致性、
> 无障碍守护自动恢复、关于页自动更新。

## 二、真机用例（需用户执行，本机无 Android 设备）

### A. 静默入账与轻打扰

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-01 | 开启自动记账，用微信完成一笔商户支付（页面含金额 + 商户） | **不弹「是否记账」**；约 1 秒内底部弹出「✓ 已自动记账 ¥xx 商户」，3 秒自动消失；账本里出现该笔，备注「商户 · 购买内容」 |
| TC-02 | 故意只让页面出现金额、商户抽不到（如纯数字转账页） | 底部弹轻确认卡片（记账 / 忽略），12 秒自动消失；不跳 App、不进通知栏 |
| TC-03 | 上述两种场景全程观察通知栏 | 无「识屏完成 · 点击确认记账」、无「记账成功」常驻通知；极端兜底横幅 8 秒自消 |
| TC-04 | 保持自动记账，锁屏/切到其它 App 后完成支付 | 轻卡片仍贴在屏幕底部（无障碍窗口类型），卡片外触摸不被拦截，不抢焦点 |

### B. 文本采集与结果一致性

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-05 | 打开同一支付成功页：先自动识屏、再摇一摇识屏 | 两次识别出的金额、商户、备注一致；诊断日志 `SCREEN` 行有合理 `len=`（数百字，不再是 2）与 `preview=` |
| TC-06 | 打开微信付款码页 / 收银台 | 日志出现 `识别到付款界面 ... len=...`，**不产生账单** |
| TC-07 | 打开微信支付成功页，等待 5 分钟 | 不再出现「只识别到『支付』」；若仍稀疏，日志出现 `未识别 ... sparse=true` 并有 `结果页重读 #1/#2/#3` |

### C. 重复检测

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-08 | 完成一笔支付后，回到微信打开**同一笔付款记录（账单详情）** | 日志出现 `账单详情（提交去重）`；底部弹「这笔已记过，已跳过」轻提示（3 秒自消），不新增账单、不发通知 |
| TC-09 | 24 小时内第三次同商户同金额支付 | 底部弹「这笔好像记过了」轻卡片（仍然记账 / 忽略），不跳 App、不进通知栏 |
| TC-10 | 点轻卡片的「忽略」 | 该次识别被丢弃，无后续弹窗 |

### D. 抖音订单页

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-11 | 抖音完成一笔订单，进入订单详情页（只有「实付 ¥xx」+「订单详情」，没有「支付成功」） | 日志 `提交识别 ... screen=SUCCESS reason=douyin:`；自动入账并弹轻卡片成功提醒；备注含商家名 |
| TC-12 | 抖音收银台（有「实付 ¥xx」但未付款） | 判为付款界面（`reason=className` 或 ENTRY），**不自动记账** |

### E. 无障碍守护 / 自动恢复

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-13 | 先跑 `bash scripts/android_unlock_accessibility.sh restore`（USB 调试），然后手动在系统关闭无障碍开关 | 60 秒内守护自动写回系统设置，服务重新连接；日志出现「守护服务自动恢复无障碍授权成功」；整个过程不需要手动再开 |

| TC-15 | 观察通知栏 | 「少花点儿 · 无障碍守护」为 IMPORTANCE_MIN 静默通知（折叠区、不弹横幅） |

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-16 | 关于页点「检查 GitHub 更新」，当前已是最新版 | 提示「已是最新版本 v1.3.1」 |

## 三、已知边界

- 系统不允许普通 App 静默安装：TC-17 最后一步必须用户点系统安装器的「安装」。
- 未授予 `WRITE_SECURE_SETTINGS` 时，守护只能检测 + 轻提醒，不能替用户改系统开关（TC-14）。
- 自动更新只读取 GitHub 公开 Releases；账单数据仍不上传。
- 页面识别是启发式（类名 + 文案），新文案可能漏判；漏判时把 `SCREEN` 行的 `cls=` / `len=` / `preview=` 发给开发者补规则。
