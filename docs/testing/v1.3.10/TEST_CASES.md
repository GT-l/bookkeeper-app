# v1.3.10 测试用例：商户名被识别成「全称」

## 一、缺陷描述

用户在微信「账单详情」页识屏，商户名被写成 **「全称」** 两个字，而不是真实商户。

## 二、根因

微信账单详情版式：

```
账单详情
-18.60
已支付
商户全称
瑞幸咖啡（北京）有限公司
收单机构
财付通支付科技有限公司
```

两条链路同时中招：

| 链路 | 问题 |
| --- | --- |
| `PaymentTextAnalyzer.extractBestMerchant` | 正则 `(?:…\|商户全称\|商户\|…)` 匹配「商户全称」后，`([^ ：:]{2,30})` 需要至少 2 个字符，行尾已结束 → **回溯成「商户」+「全称」**，「全称」恰为 2 字，直接当商户名返回 |
| `PaymentScreenRecognizer.extractLabelledMerchant` | 微信无障碍有时把标签拆成「商户」「全称」两个节点 → `removePrefix("商户")` 得到 `inline="全称"`，长度 2 通过校验 → 补出 `商户：全称`，再被分析器原样读出 |

## 三、修复方案

1. 新增 `MERCHANT_LABEL_FRAGMENTS = {全称, 简称, 名称, 商户全称, 商户简称, 商户名称}`，**任何链路都不允许把它当商户值**。
2. 「标签独占一行」分支改为**向下扫描最多 3 行**：残片跳过继续找；遇到非残片又不合法的行（如「收单机构」）立即停止，不越界取到通道方。
3. 兜底猜测用的 `NOISE_LINES` 加入「全称 / 简称 / 名称」。
4. 拿不到可信商户时**宁可不补**，备注只写购买内容，绝不写错。

## 四、功能用例

| 编号 | 场景 | 输入 | 期望 |
| --- | --- | --- | --- |
| F-01 | 标签同行 | `商户全称 星巴克咖啡有限公司` | 商户 = 星巴克咖啡有限公司 |
| F-02 | 标签独占一行 | `商户全称` / `全家便利店` | 商户 = 全家便利店 |
| F-03 | 标签被拆两个节点 | `商户` / `全称` / `瑞幸咖啡（北京）有限公司` | 商户 = 瑞幸咖啡（北京）有限公司 |
| F-04 | 只有残片无真值 | `商户` / `全称` / `收单机构` / `财付通支付科技有限公司` | 商户 = 空（不写「全称」、不写收单机构） |
| F-05 | 纯标签行 | 全文只有 `商户全称` | 商户 = 空 |
| F-06 | 带冒号标签 | `商户简称：` | 商户 = 空 |
| F-07 | 收单机构仍被排除 | `收单机构` / `财付通支付科技有限公司` | 商户 = 空，金额正常 |
| F-08 | 正常商户不受影响 | `商户 全聚德烤鸭店` | 商户 = 全聚德烤鸭店 |

## 五、回归用例

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| R-01 | 金额为独立 `-18.60` 行 | 金额 = 18.60 |
| R-02 | 金额行含「优惠」 | 不覆盖实付金额 |
| R-03 | 支付宝账单详情（标签同行） | 商户正常 |
| R-04 | 抖音订单页 | 金额与商家正常 |
| R-05 | 红包 / 转账四场景 | 识别结果与 v1.3.9 一致 |
