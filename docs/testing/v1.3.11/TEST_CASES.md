# v1.3.11 测试用例：微信账单详情 / 收款成功页识别与交易时间判重

## 一、缺陷现象

用户反馈两张微信页面「又识别不出来了」，并指出「转账记录这类要识别记录时间来判断是否重复」。

### 页面 A：微信支付账单详情（Apple）

```
Apple
-16.00
当前状态    支付成功
支付时间    2026年11月15日 00:00:07
商品        apple.com/bill/MLF37524K0a0
商户全称    Apple Distribution International
            limited
收单机构    财付通支付科技有限公司
支付方式    零钱
交易单号    4200003217202611151634196683
商户单号    MLF37524K0a0
```

### 页面 B：微信收款成功

```
你已收款，资金已存入零钱
¥100.00
零钱余额
转账时间    2026年11月28日 10:55:25
收款时间    2026年11月28日 10:55:38
账单详情
```

## 二、应该记什么

| 页面 | 类型 | 金额 | 商户 / 备注 | 账单时间 |
| --- | --- | --- | --- | --- |
| A Apple | 支出 | 16.00 | Apple Distribution International limited | 2026-11-15 00:00:07 |
| B 收款 | 收入 | 100.00 | 微信收款 | 2026-11-28 10:55:25 |

## 三、根因（三条）

**1. 英文商户名被节点拆成两行**

`Apple Distribution International` 单行 32 字符，超过商户长度上限 30；`limited` 在下一行。旧逻辑取第一行判定超长直接 `break`，商户为空。

**2. 收款页 / 详情页必然进确认队列**

六因子置信度中商户因子占 0.10。收款页天然没有商户名（钱是转给某个人），账单页旧版也抽不到商户：

```
0.30(OCR) + 0.25(金额) + 0.15(时间) + 0 + 0 + 0 + 0.05(页面加成) = 0.75
```

刚好压在默认阈值 0.75 上；一旦账户 / 分类为空，`invalidBillFields` 直接把它丢进确认队列。用户不点，表现就是「识别不出来」。

**3. 重复判定只看识屏时刻**

`billTime` 走的是 `fields.billTime`，页面时间抽不到时回退到「识屏时刻」。同一笔账单反复打开，时间每次都不同 → 去重键不同 → 可能重复记账；反过来，连续看两笔同金额账单时又被 12 秒静默期吞掉。

## 四、修复

1. **英文续行拼接**：`mergeLatinContinuation` 在「首行无中日韩文字且下一行也是纯英文」时拼接两行（字段上限放宽到 60），中文商户不受影响。
2. **账单链接不当购买内容**：`GOODS_EXCLUDES` 增加 `http` / `www.` / `.com/` / `.cn/` / `/bill/`。
3. **页面类型加成分级**：读屏来源且金额有效时，成功页 +0.20、账单详情页 +0.10，不再要求必须有商户名。
4. **账户兜底**：读屏且金额有效、规则没映射到账户时，用账本第一个账户；避免恒判「字段不完整」。
5. **交易时间判重**：新增 `transactionTimeKey()` 抽取「支付时间 / 转账时间 / 收款时间 / 交易时间 / 到账时间 / 创建时间」；静默标记增加 `timeKey`，不同时间说明是另一笔 → 放行；同一笔重复触发时间一致 → 继续静默。

## 五、功能用例

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| F-01 | Apple 账单详情 | 支出 16.00，商户 `Apple Distribution International limited` |
| F-02 | Apple 账单「商品」为账单链接 | 购买内容为空，备注不出现 URL |
| F-03 | 收款成功页 | 收入 100.00，备注「微信收款」 |
| F-04 | 收款页无商户名 | 仍自动入账，不进确认队列 |
| F-05 | 页面无账户信息（微信零钱） | 用账本第一个账户兜底 |
| F-06 | 同一笔账单反复打开 | 时间一致 → 判重复，不重复记账 |
| F-07 | 两笔同金额不同时间转账 | 时间不同 → 各记一笔 |
| F-08 | 页面无时间字段 | `transactionTimeKey` 返回空，退回识屏时刻 |

## 八、边界说明

- 「商品」字段单独成行（不是「商品说明」）时，标签本身不在购买内容标签表里，购买内容会留空——这是有意的：宁可不填，也不把账单号写进备注。
- 交易时间优先取带标签的行；页面无标签时才退化为整页第一个日期，若页面混入其它日期可能取错，但比识屏时刻更接近真实。
- 两笔转账若落在同一分钟且金额相同、页面时间只精确到分钟，仍会被判重复（概率极低）。
