# v1.3.13 测试用例

## 一、本版范围

只做「可观测性 + 存储排查 + 授权体检」，**不改识别规则**（原因见 `PLAN.md`）。

## 二、用例

### A. 无障碍事件到达（核心）

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| A-01 | 打开自检页，不做任何操作 | 显示「今天 N 条（支付应用 M 条）· 最后一条 …」 |
| A-02 | 在微信里上下滑动、切换页面，回自检页刷新 | N 与 M 都增长，最后包名以 `com.tencent.mm` 结尾 |
| A-03 | 关闭系统无障碍开关，再进微信滑动 | N 不再增长（证明统计只反映真实投递） |
| A-04 | 重新打开无障碍，微信滑动 | N 恢复增长 |
| A-05 | 跨天后再看 | 计数从 0 重新开始（按天重置） |

### B. 授权体检

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| B-01 | 关闭无障碍 → 回到 App | 1 秒内出现「识屏被关闭」通知 |
| B-02 | 已有 WRITE_SECURE_SETTINGS + 关闭无障碍 → 回到 App | 自动写回，自检页显示已开启 |
| B-03 | 覆盖安装新版本 → 打开 App | 不静默：要么自动恢复，要么有通知 |

### C. 存储排查

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| C-01 | 检查更新下载一次 APK 但取消安装 → 进存储排查 | 「安装包残留」分类下出现 `updates/incoming.apk`，约 90MB |
| C-02 | 勾选并删除 | 文件消失，体积统计更新 |
| C-03 | 查看日志行 | `capture_log.txt` 标注「识屏日志（自检页「复制 log」的来源）」 |
| C-04 | 数据库与密钥行 | 仍为锁定，无法勾选 |

### D. 日志默认开启

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| D-01 | 全新安装后进微信页面 | `capture_log.txt` 自动产生且持续写入 |
| D-02 | 设置里关闭识屏日志 | 之后不再写入；重新打开恢复 |
