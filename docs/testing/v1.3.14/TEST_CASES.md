# v1.3.14 测试用例：抖音订单页重复识别

## 一、现象

抖音订单页（实付 ¥xx + 订单详情）会重复记账，同一笔订单可能出现 2~3 条。

## 二、根因

抖音订单页事件极其密集（图片懒加载、滚动、状态刷新都会触发 `TYPE_WINDOW_CONTENT_CHANGED`）。
`submitCapture` 有两道闸：

1. **内容指纹 5 秒冷却**（`SUCCESS_DEDUP_MS`）
2. **包名静默期 12 秒 + 金额指纹**

两道闸都只能挡住"短时间内的连续触发"。用户在订单页停留超过 12 秒（看商品、截图、切回再进来），
就会重新提交。此时进入 `CaptureCoordinator` 的去重：

```
去重键 = bookId | 秒级 billTime | 金额 | 账户 | 归一化备注
```

`billTime` 来自 `fields.billTime`，而字段抽取拿不到页面时间时回退到 **`event.billTime`（识屏时刻）**。
同一笔订单每次识屏的时刻都不同 → **去重键每次都不同** → 去重完全失效 → 重复记账。

这就是"抖音重复识别"的真正原因，与识别词表无关。

## 三、修复

1. **账单时间优先用页面时间**（`CaptureCoordinator`）
   - `PaymentScreenRecognizer.transactionTimeKey(rawText)` 抽「支付时间 / 转账时间 / 收款时间 / 交易时间 / 到账时间 / 下单时间…」
   - 解析成功即覆盖 `fields.billTime`
   - 同一笔反复识屏 → 时间一致 → 去重键一致 → 判重
2. **抖音静默窗口 12s → 60s**（`PaymentAccessibilityService`）
   - 部分抖音订单页不写下单时间，只能靠更长的静默窗口兜住同订单的重复提交
   - 只对 `PaymentScene.DOUYIN_ORDER` 生效，不影响微信/支付宝的连续查看

## 四、用例

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| D-01 | 抖音订单页停留 30 秒不动 | 只入账 1 笔 |
| D-02 | 抖音订单页来回切走再切回（3 次） | 只入账 1 笔 |
| D-03 | 抖音页面含「下单时间 2026-11-28 10:55:00」 | 账单时间 = 该时间，不是识屏时刻 |
| D-04 | 抖音订单页无任何时间字段 | 60 秒内重复触发不重复入账 |
| D-05 | 两笔不同订单（金额相同、下单时间不同） | 各入账 1 笔 |
| D-06 | 微信账单详情连续看两笔 | 不受 60 秒窗口影响，仍各记一笔 |
| D-07 | 抖音收银台（有实付但非订单上下文） | 不识别为成功页，不记账 |

## 七、边界

- 抖音订单页既没有下单时间、用户又停留超过 60 秒并再次触发时，仍可能重复；此时去重回到"识屏时刻"逻辑，属于已知限制。
- 若抖音订单页的「下单时间」只精确到分钟，同一分钟内两笔同金额订单会被判重复（概率极低）。
