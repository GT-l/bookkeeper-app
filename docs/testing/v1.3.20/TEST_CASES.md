# v1.3.20 识别硬闸与旧版本清理

## 一、原则

**宁可漏记，不可错记。** 不确定的界面一律不自动触发，等用户手势主动记账。
用户主动记账不受任何限制约束。

## 二、触发硬闸

| 场景 | 实现 |
| --- | --- |
| 抖音列表页 | `hasOrderId(text)`：必须有「订单号 / 交易单号 / 订单编号 + 数字」；类名与文案分支都加这道闸。只有商家名 + 金额 → UNKNOWN |
| 微信聊天页 | 类名外增加结构性提示（`按住说话 / 发消息 / 输入消息`）排除；提示出现即 UNKNOWN，即使有「支付成功」字样。不读消息正文 |
| 中间态 | `待支付/待付款/支付中/处理中/待确认` 加入 PENDING_TRANSFER；但成功词共存时不拦截（避免「已支付成功 + 待收货」被误判） |
| 金额优先级 | FieldExtractor 新增 `amountFinal`（实付/应付/合计/支付金额）作为最高优先候选；`小计/原价/优惠/运费/商品总价` 行一律跳过 |
| 去重 | 沿用 v1.3.14 起的页面交易时间 + 金额 + 备注键；退款作为收入/冲正单独处理 |

## 三、存储排查

### 为什么覆盖安装后还能看到旧偏好文件

Android 的**覆盖安装不会清除 `/data/data/<package>`**，只替换 APK。
`shared_prefs/*.xml` 是应用自己写的偏好文件，只要包名不变就会一直留着，
哪怕对应的字段早就被新版本弃用。只有**卸载重装**才会清空整个私有目录。

### 一键清理

- VM 新增 `selectObsolete()`：选中 `LOG / CACHE / APK / PREF / DATABASE / OTHER` 中未锁定的项；
- **BACKUP 永不自动选中**——备份是用户恢复凭据，只能手动逐项勾选；
- 选中后仍走原有二次确认弹窗，不会点一下就删；
- 页面文案补上覆盖安装不清数据的说明。

| G-07 | 一键选中旧版本残留 | 可清理项全选，备份包不选，仍需确认 |
