目标：**微信支付场景全触发 + 商户改为金额上方定位**。

## 一、问题四：付款方式被识别成商户名

### 真机结构线索（用户提供）

> 真正的付款接收方只在付款金额的上方提示，而不是下面那一堆字。

旧兜底规则在整页找「带后缀的独立行」，`招商银行储蓄卡` 含「银行」二字被命中；
真实收款方在金额上方却没有被优先读取。

### 规则（受 [问题四-位置规则] 约束）

`PaymentMerchantLocator.locateAboveAmount(lines)`：找到金额行，向上最多 4 行，
取第一条有效收款方。排除：付款方式、银行卡/储蓄卡/信用卡/尾号、通道名（财付通/网联/银联）、
状态行、金额行、时间行、单号行、UI 按钮。向上无命中返回 null，不向下猜。

接入位置：`PaymentTextAnalyzer.analyze()` 中作为**最高优先级**商户路径，
未命中才走原标签抽取，最后才是规则一的通道回溯。

| 用例 | 原文 | 期望 |

| TC-M1 | `支付成功 / 喜茶点单小程序 / ¥21.60 / 付款方式：招商银行储蓄卡(1234) / 交易单号：4200001234` | merchant=`喜茶点单小程序` |
| TC-M2 | `喜茶点单小程序 / 支付成功 / ¥21.60 / 付款方式：零钱` | 跨过状态行，merchant=`喜茶点单小程序` |

## 二、问题一：微信支付场景全触发

### 判据（受 [问题一-全场景触发] 约束）

`WechatPayFinalPageResolver.isFinalPayPage(text)` = 完成态 + 金额 + 非中间态。

- 完成态覆盖：扫码/付款码/公众号/小程序/第三方拉起支付的「支付成功/支付完成/交易完成」，
  转账收发「转账成功/已收钱/已存入对方零钱」，红包收发「红包已领取/红包已发出」，
  单笔详情「账单详情/交易详情/订单详情」。
- 中间态一律拒绝：待支付/未支付/支付中/确认收款/确认支付/付款码/收银台/选择付款方式。
- 聊天页结构提示（按住说话/发消息）一律拒绝，聊天气泡里的「支付成功」不可信。
- 退款页拒绝（冲正不是新支出）。
- 无金额不猜。

### 接入点

在 `PaymentAccessibilityService.dispatchEvent()` 中把判定提到 `when` 之前：

- 原本判 `ENTRY` 但实为已完成支付（页面带「支付金额」标签）→ 不解除静默、不缓存，
  直接按最终页提交；
- 原本判 `UNKNOWN` 且 `looksLikeReceipt` 不命中 → 用 `wechatFinal` 兜底提交；
- 提交时带上正确的 `scene` / `direction`，保证备注前缀与去重口径正确。

**冻结文件 `PaymentScreenRecognizer.kt` 未改一个字**（静态脚本 SHA-256 钉住），
本模块是独立补充，转账/红包词表与状态机保持原样。
