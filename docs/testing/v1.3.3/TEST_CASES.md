# v1.3.3 测试用例

> 测试对象：`v1.3.3`（versionCode 10）。本轮只改「检查更新 / 下载 APK」链路：
> 下载失败要显示具体原因、双通道自动降级、失败可走浏览器或本地 APK 兜底；
> 不动识屏、记账、无障碍逻辑。

## 一、自动验证

| 项目 | 命令 | 判定 |
| --- | --- | --- |
| 静态一致性 | `python3 scripts/verify_v1_3_3.py` | 全部 PASS |
| Kotlin 编译 | CI `assembleDebug` | 成功 |
| JVM 单测 | CI `testDebugUnitTest` | `T*-F0-E0-S0` |

新增单测：`GithubUpdateCheckerTest` 补充「错误提示包含 CDN 域名放行建议」「浏览器下载链接回退」
「下载结果按文件与错误判定成功失败」三例。

## 二、真机用例

### A. 下载失败可见（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-01 | 关闭代理，在关于页点「检查更新」 | 若能获取到新版本，下载失败时提示里必须写清 `HTTP xxx @ 具体域名`，不再只有「请检查网络」 |
| TC-02 | 开启 Clash 且规则**不**放行 `githubusercontent.com`，再点检查更新 | 下载失败提示包含 `release-assets.githubusercontent.com` 与「放行 githubusercontent.com / TUN 模式」建议 |
| TC-03 | Clash 开 TUN / 全局模式并放行该域名，再点检查更新 | 自动下载成功 → 进度到 100% → 自动打开系统安装器 |
| TC-04 | 检查更新接口本身失败（如 api.github.com 不通） | 提示写明 `api.github.com 返回 HTTP xxx`，不是泛化错误 |

### B. 双通道与文件完整性

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-05 | 模拟主通道（GitHub asset API）返回 403、备用通道正常 | 自动降级到备用通道并下载成功，UI 不报错 |
| TC-06 | 代理返回 HTML 拦截页（HTTP 200 但内容非 APK） | 提示「不是有效 APK」，不拉起安装器 |
| TC-07 | 下载中途断网 | 清理 `.part` 临时文件，不留半截 APK；再次检查更新可重新开始 |
| TC-08 | 下载完成后覆盖安装旧版 | 同签名直接覆盖，账单不丢（版本码 10 > 9） |

### C. 兜底路径

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-09 | 下载失败后点「用浏览器下载」 | 系统浏览器打开 releases 页面；浏览器沿用 Clash 配置可完成下载 |
| TC-10 | 在 PC 上用代理下载 APK 传到手机，点「选本地 APK」选中它 | 直接拉起系统安装器，点「安装」完成覆盖 |
| TC-11 | 选到一个非 APK 文件 | 提示「这个文件不是可安装的 APK」，不拉起安装器 |

### D. 回归（确保没动其它链路）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-12 | 完成一笔支付触发识屏 | 高置信度仍静默入账 + 3 秒轻提示，行为与 v1.3.2 一致 |
| TC-13 | 下拉通知栏 | 仍只有一条「自动记账」常驻通知 |
| TC-14 | 关于页更新介绍 | 首条为 v1.3.3，旧条目保留可读 |

## 三、边界（如实说明）

- App 无法代替用户配置 Clash 规则；只保证把「卡在哪个域名、HTTP 几」说清楚，并给出可照做的建议。
- Android 普通 App 不读取 HTTP 代理软件（非 TUN 模式）的代理设置；此场景必须走浏览器下载或本地安装。
- 最后一步安装仍需用户点系统页面的「安装」，这是 Android 的强制要求。
