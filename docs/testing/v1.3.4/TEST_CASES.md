## 二、真机用例

### A. 识屏不再误判重复（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-01 | 微信完成一笔支付，停留在成功页 5~10 秒 | 只入账 1 笔、只弹一次「记下啦」，不再出现「这笔已记过」 |
| TC-02 | 支付宝完成一笔支付，成功页文字逐步加载 | 同上，多次事件潮只提交一次 |
| TC-03 | 抖音订单页完成支付，快速切换页面 | 只入账 1 笔，不误弹重复 |
| TC-04 | 完成一笔后返回收银台再付第二笔（同金额同商户） | ENTRY 解锁静默期，第二笔正常进入去重判定，符合预期 |
| TC-05 | 同一笔被不同源（读屏 + 通知）都识别到 | 重复提醒 8 秒内只弹一次，不连续弹多张卡片 |

### B. 弹窗样式（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-06 | 触发自动记账成功轻提示 | 奶油白圆角卡片 + 小猪存钱罐图标 + 「记下啦 ¥xx 商户」+「今天也有认真记账哦～」，3 秒消失 |
| TC-07 | 触发重复跳过提示 | 同款卡片，文案「这笔已记过，先跳过啦」+「避免重复记账，放心～」 |
| TC-08 | 触发低置信度确认卡片 | 同款卡片，胶囊按钮「记一笔 / 忽略」，点「记一笔」正常落库 |
| TC-09 | 浅色 / 深色主题各看一次 | 两种主题都可读，金额草莓粉对比清晰，不遮挡卡片外操作 |

## 三、边界（如实说明）

- 静默期 12 秒是「同一轮支付」的近似判定；用户若在成功页停留后直接从另一入口完成第二笔（未经收银台 ENTRY），可能被静默吞掉一次，属已知取舍。
- 队列事件潮下若金额/备注完全一致，8 秒节流只提示一次，账单本身不会重复写入（去重在写库前拦截）。
