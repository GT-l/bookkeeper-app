# v1.3.5 测试用例

> 测试对象：`v1.3.5`（versionCode 12）。本轮修消费记录自动识别命中率、取消/黑屏、安装包残留，弹窗再美化。

## 一、自动验证

| 项目 | 命令 | 判定 |
| --- | --- | --- |
| 静态一致性 | `python3 scripts/verify_v1_3_5.py` | 全部 PASS |
| Kotlin 编译 | CI `assembleDebug` | 成功 |
| JVM 单测 | CI `testDebugUnitTest` | `T*-F0-E0-S0` |

## 二、真机用例

### A. 消费记录自动识别（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-01 | 微信 → 我 → 服务 → 钱包 → 账单 → 点进一笔消费 | 页面出现后自动识别为「消费记录」，高置信度直接入账或弹轻卡片确认，**不需要摇一摇** |
| TC-02 | 支付宝账单 → 点进一笔交易详情 | 同上，含「交易单号 / 支付时间」的页面必须命中 |
| TC-03 | 连续点开两笔不同金额的消费记录（间隔 < 12 秒） | 两笔都能识别，第二笔不被静默吞掉 |
| TC-04 | 打开只有「消费记录」标题、金额行很多的账单列表 | 不把列表当一笔自动入账 |
| TC-05 | 微信聊天里出现「¥100」 | 不触发识别（缺少交易单号等凭据字段） |

### B. 取消 / 黑屏（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-06 | 摇一摇识屏失败（对准无文字的空白页） | 只弹轻卡片「没识别到这笔，要手动记吗？」或一条通知，**不自动打开记账页** |
| TC-07 | 在 TC-06 的轻卡片点「手动记一笔」 | 打开表单；点「取消」能回到首页，不再无反应 |
| TC-08 | 从桌面/通知直接打开记账表单（表单是唯一页面），点「取消」 | 回到首页；按系统返回也回首页，不出现黑屏 |
| TC-09 | 截屏授权页弹出后按返回/取消 | 15 秒内自动关闭，不停留成黑屏 |
| TC-10 | 识屏轻确认卡片（QuickConfirm）打开后不操作 | 25 秒自动关闭，返回也不黑屏 |

### C. 安装包清理

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-11 | 关于页检查更新 → 下载 → 自动打开安装器 → 完成安装 | 约 2 分钟后 `filesDir/updates` 下的 APK 被删除 |
| TC-12 | 下载后不安装，退出 App 一小时后再检查更新 | 旧 APK 被清理，重新下载正常 |

## 三、边界（如实说明）

- 消费记录识别仍是启发式：不同 App 版本页面结构会变，靠「强字段 + 金额行数」判断，极端页面可能仍需手动确认。
- 静默期按「包名 + 金额」判断，同金额的两笔在 12 秒内仍可能被合并一次，属已知取舍。
- 安装包延迟 2 分钟删除；若进程被杀，下次检查更新时兜底清理。
