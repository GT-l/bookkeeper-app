# v1.3.6 测试用例

> 测试对象：`v1.3.6`（versionCode 13）。本轮按支付场景专门处理转账/收款，并新增「支付前缓存 → 支付后补齐」。

## 一、自动验证

| 项目 | 命令 | 判定 |
| --- | --- | --- |
| 静态一致性 | `python3 scripts/verify_v1_3_6.py` | 全部 PASS |
| Kotlin 编译 | CI `assembleDebug` | 成功 |
| JVM 单测 | CI `testDebugUnitTest` | `T*-F0-E0-S0` |

新增单测：微信「已收钱」识别为收款、跨行「已\\n收钱」、转出记支出、待确认收款不记账、支付宝转账、转账结果页类名。

## 二、覆盖的支付场景

| 场景 | 识别依据 | 方向 |
| --- | --- | --- |
| 微信转出（转账成功 / 已存入对方零钱 / 转账已发出） | 转出词 + 类名 | 支出 |
| 微信收款（已收钱 / 已收款 / 收款成功 / 已存入零钱） | 收入词优先 | 收入 |
| 微信红包（红包已发送 / 已领取） | 红包词 | 支出 / 收入 |
| 微信商户付款（付款码 / 收银台 / 小程序） | 付款界面 → 成功页 | 支出 |
| 微信账单详情（交易单号 / 商户单号 / 支付时间） | 详情强字段 | 支出 |
| 支付宝转账 / 收款（转账成功 / 收款成功 / 已收款） | 转账词 + 收入词 | 支出 / 收入 |
| 支付宝账单详情（订单号 / 商家交易号） | 详情字段 | 支出 |
| 抖音订单（实付 + 订单详情） | 订单字段 | 支出 |
| 银行 / 云闪付等（到达率低） | 通用成功词 | 支出 |

## 三、真机用例

### A. 转账 / 收款（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-01 | 微信给好友转账，输入密码完成 | 成功页自动识别，记为**支出**，只入账一次 |
| TC-02 | 对方视角：点开转账 → 确认收款 | 显示「已收钱」时自动识别，记为**收入** |
| TC-03 | 转账后对方未确认（待确认收款） | 不记账；点确认收款后才入账 |
| TC-04 | 支付宝转账成功 / 收款成功 | 分别记支出 / 收入 |
| TC-05 | 转账页面文字被拆成两行（已 / 收钱） | 仍能识别 |
| TC-06 | 打开微信账单详情（交易单号页） | 识别为详情，不重复入账 |

### B. 支付前缓存（本轮重点）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-07 | 在收银台停留 3~5 秒再输密码 | 成功页金额缺失时用收银台缓存的金额补齐，直接入账 |
| TC-08 | 收银台打开后放弃支付，5 分钟后再付另一笔 | 缓存过期，不会把上一笔金额带到新账单 |

### C. 回归

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| TC-09 | 扫码买咖啡 | 仍只入账一次，无重复提醒 |
| TC-10 | 打开消费记录（v1.3.5 修复） | 仍能识别 |
| TC-11 | 摇一摇识屏失败 | 不自动跳表单，只弹轻卡片/通知 |
| TC-12 | 检查更新安装完成 | 约 2 分钟后安装包被删除 |

## 四、边界（如实说明）

- 「待确认收款」阶段钱未真正到账，不记账；确认收款后才记收入。
- 收入账单的分类取「默认收入分类 / 其他」，规则未命中时不会记成支出分类。
- 银行类 App 包名不在白名单的仍不会读屏；这类场景主要靠通知/短信链路。
