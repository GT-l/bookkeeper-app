## 本轮结论

- **转账 / 收款识别**：微信收款成功实际文案是「已收钱」，旧词表只有「已收款」→ 现已覆盖；
  同时用紧凑文本匹配解决「已 / 收钱」「转账 / 成功」被拆到不同节点的问题。
- **方向判定**：收款词优先，转账/红包收款记收入（`BillType.INCOME`），转出记支出；
  「待确认收款」为中间态不记账。
- **支付前缓存**：进入收银台时缓存金额/商户（5 分钟），成功页字段缺失自动补齐。
- **场景化**：微信转账/收款/红包/商户付款/账单详情、支付宝转账/收款/账单详情、抖音订单分别归类。
- 收入分类兜底取「默认收入分类 / 其他」，不再记成支出分类。

## 边界

- 识别仍是文案 + 类名启发式，微信改版文案时需要同步词表。
- 银行类 App 包名不在白名单的仍不走读屏，主要依赖通知/短信链路。
- 真机用例 TC-01~TC-12 无设备未执行，不记通过。
