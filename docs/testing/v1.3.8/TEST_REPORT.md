## 二、本轮修复的四个真实问题

### 1. 红包完全识别不到

v1.3.6 的 `WECHAT_SUCCESS` 只有「已收款 / 已到账」，没有任何红包词。
微信收红包后的页面写的是「¥10.00 / 已存入零钱 / 恭喜发财，大吉大利」，
发红包后写「红包已发送 / 已存入对方零钱」——两页都判 UNKNOWN。

现在：红包上下文（红包 / 恭喜发财 / 拼手气 / 手气最佳）+ 收/发信号**双条件**命中，
分别产出 `WECHAT_RED_PACKET_IN`（收入）与 `WECHAT_RED_PACKET_OUT`（支出）。

### 2. 转账方向会串

v1.3.6 把「对方已收款」放进了 `TRANSFER_IN_HINTS`。但这句话是**转出方**看到的——
我把钱转给对方、对方收了。结果自己转出去的账被记成收入。

现在：「对方已收款 / 对方已领取」归入 `TRANSFER_OUT_HINTS`，
并且 `directionOf()` 改成转出优先，避免任何「转账成功」类文案落到收入。

### 3. 聊天页被当成支付成功

微信聊天列表 / 聊天页里必然出现「微信支付」（服务号名称）和转账气泡的「已收款」，
旧词表会把整页判成 SUCCESS 并直接记账。这是最隐蔽的脏账来源。

现在：`CHAT_CLASS_TOKENS`（ChattingUI / LauncherUI / ConversationUI 等）整页跳过，
返回 UNKNOWN、confidence=0，不提交、不重试。

### 4. 识屏失效是静默的

无障碍被系统撤销后，用户付完钱什么都不会发生。钱迹/一木都把运行状态放在通知栏。

现在：`CaptureHealthNotifier` 在守护检查发现识屏不可用时推一条**非常驻**通知
（独立渠道「识屏状态提醒」，IMPORTANCE_LOW 不响铃）：
- 点正文 → 直接进「记一笔」；
- 点「去开启」→ 系统无障碍设置；
- 识屏恢复（onServiceConnected 或守护检查）→ 自动撤销，并清零节流。

## 三、市面产品调研结论（本轮落地的部分）

| 产品 | 支持场景 | 本版是否已覆盖 |
| --- | --- | --- |
| 钱迹 | 支付宝/微信支付页、云闪付；强调「支付保护」会让悬浮窗不显示 | 支付页 ✅、云闪付 ✅ |
| 一木记账 | 支付宝/微信：扫码付款、转账、红包、提现、账单详情；云闪付；京东/淘宝/美团等电商 | 前五项 ✅，电商 ❌（见边界） |
| 咔皮记账 | 无障碍 + 通知卡快捷「截屏识别」，AI 去重 | 无障碍 ✅、手动记一笔入口 ✅、AI 去重 ❌ |

本版新增落地：红包收发、转账双方向、云闪付白名单、提现/充值判内部划转（不入账）。

## 四、边界与风险

1. 红包页若完全没有红包上下文词，会按「转账收入」处理：金额和方向正确，仅备注前缀不同。
2. 微信类名会随版本变化，类名只作增强信号，文案仍是主路径。
3. 识屏提醒依赖自动记账前台服务的 15 秒守护；自动化总开关关闭时不提醒。
4. 电商页面（淘宝/京东/拼多多/美团）未纳入：页面结构差异大、误报风险高，需真机样本后再做。
5. 真机用例（D138-01 ~ D138-14）需在设备上执行，本报告只覆盖静态与单测。
